# ADSB Historical Route Builder — User Guide

A practical, walk-through guide to the **Route Builder** GUI and every setting it exposes:
what each control does, what to pick, and worked end-to-end examples. It complements the
[README](../README.md) (which is the reference); this is the "how do I actually run a batch"
guide.

> single most common thing people get wrong.**

## 1. The two-file rule (read this first)

The splitter needs **two small reference CSVs**, both **generated by `build_cirium_inputs.py`**
and both keyed by **ICAO**:

| Field in the UI | File you select | Header | What it is |
|---|---|---|---|
| **Airports CSV** | `input/<airline>_<period>_airports.csv` | `airport,latitude,longitude,elevation_ft` | Every airport referenced by the routes, with coordinates. |
| **Routes-time CSV** | `input/<airline>_<period>_routes_time.csv` | `origin,destination,avg_enroute_min` | Scheduled enroute time per route (used to rescue truncated flights). |

**These are NOT:**

- ❌ `input/Airports_2511.txt` (or `Airports_2606.txt`) — that's the big **OurAirports lookup
  database**. It's used *only* by `build_cirium_inputs.py` to resolve coordinates; the splitter
  does **not** read it, and its format is different. Selecting it as "Airports CSV" will fail.
- ❌ `input/<airline>_route_cirium_<period>.csv` — that's the **raw Cirium schedule export**.
  It's the *input* to `build_cirium_inputs.py`, not to the splitter. It has columns like
  `Orig, Dest, Flights, Block Mins` — the wrong shape for both `--airports` and `--routes`.

If you don't yet have the two generated CSVs for your airline, **build them first** (§4).

## 2. The end-to-end workflow

```
Cirium schedule export                ADS-B KML tracks
(input/<airline>_route_cirium_*.csv)  (~/Git/kml/adsb_kml_downloader/output/<batch>/)
          │                                        │
          ▼                                        │
  build_cirium_inputs.py  ──►  <airline>_airports.csv                │
                               <airline>_routes_time.csv             │
          │                                        │                 │
          └──────────────►  Route Builder (adsb_historical_routes.py) ◄──┘
                                        │
                                        ▼
                          output/<airline>_routes_<period>.kml
                          + .diagnostics.csv sidecar
```

**Step A — build the reference inputs** (once per airline/period), currently a command-line
pre-processing step (§4).
**Step B — split the tracks** in the Route Builder GUI (§3, §5).

> **Planned:** Step A will get its own tab in the GUI so the whole pipeline is terminal-free.
> For now it's a single command.

## 3. Launching the GUI

From the repo root (`~/Git/kml/adsb_historical_routes`):

```bash
python3 route_builder/server.py --open
```

- Opens `http://127.0.0.1:8765` in your browser.
- `--port N` uses a different port (e.g. `--open --port 8080`).
- Or **double-click `route_builder/Route Builder.command`** in Finder — no terminal.

The server binds to `127.0.0.1` only (nothing is exposed on the network). It runs
`adsb_historical_routes.py` locally as a subprocess and streams its output to the page. Press
**Ctrl-C** in the terminal (or close the tab and stop the process) to shut it down. No install,
no dependencies — Python 3 standard library only.

## 4. Building the input CSVs (Cirium)

Run this once per airline/period to turn a raw Cirium export into the two files the splitter
needs:

```bash
python3 build_cirium_inputs.py \
    --input  input/<airline>_route_cirium_<period>.csv \
    --output input/<airline>_<period>
```

Writes:

- `input/<airline>_<period>_airports.csv`   ← select as **Airports CSV**
- `input/<airline>_<period>_routes_time.csv` ← select as **Routes-time CSV**
- `input/<airline>_<period>_error.txt`       ← a validation report (`READY` / `NEEDS INPUT`)

**Worked example (POE / Porter, the one in this repo):**

```bash
python3 build_cirium_inputs.py \
    --input  input/poe_route_cirium_202606-202607.csv \
    --output input/poe_202606-202607
# → input/poe_202606-202607_airports.csv     (30 airports)
#   input/poe_202606-202607_routes_time.csv  (116 routes)
#   VERDICT: READY
```

Notes:
- Needs the shared **`airport_lookup`** tool (default `~/Git/conversion_tools/airport_lookup`);
  override with `--airport-lookup-dir`.
- `--airport-override airport_overrides.csv` (default) fixes airports the lookup resolves wrongly
  (e.g. Lima `LIM → SPJC`). Pass `--airport-override ignore` to disable.
- **Period mismatch is usually fine.** The route-time file is a schedule-based over-estimate used
  only to trim ADS-B routes, so a Jun–Jul reference works well for a Jul–Sept KML batch. Use a
  matching-period Cirium export if you have one.
- Read the `*_error.txt` verdict: `READY` means both files are complete; `NEEDS INPUT` lists
  routes/airports that couldn't be resolved (add them to `airport_overrides.csv` and re-run).

## 5. The Route Builder screen, section by section

The window is a **topbar** (wordmark · status chip · light/dark toggle), a **presets bar**, a
left **form** column, and a right **run panel**.

- **Presets bar** — pick a built-in or saved preset to set many knobs at once, or *Save as
  preset* to store your current settings. Applying a preset changes only the knobs it names; it
  keeps your chosen files/paths.
- **Form (left)** — collapsible sections: **Inputs · Output · Detection & sampling · Styling ·
  Gap Stitching · Position Sources**. Every field has an **ⓘ** tooltip with a one-line
  explanation and an example.
- **Run panel (right)** — a **pre-flight card** (file/airport/route counts, the exact command
  line that will run, and any blocking errors), the **Run** button, a live **progress bar + ETA +
  console**, and finally a **✓/✗ result** with the run summary and a *Reveal in Finder* button.

Workflow: pick inputs → pick output → choose a preset (or tune) → check the pre-flight card →
**Run** → review the result → *Run another batch* (keeps your settings).

## 6. Every setting, explained

Values in **bold** are the recommended starting points. Anything left blank uses the preset/script
default shown.

### Inputs

| Setting | What it does | Recommended |
|---|---|---|
| **Input KML folder / Select files** | The ADS-B tracks to process. "Whole folder" processes every `.kml` in a batch (the normal case, thousands of per-tail/per-day files); "Select files" runs a subset (handy for a quick test). | Whole folder for a real run; a few files to test. |
| **Airports CSV** | The generated `*_airports.csv` (§1). | `input/<airline>_<period>_airports.csv` |
| **Routes-time CSV** | The generated `*_routes_time.csv` (§1). | `input/<airline>_<period>_routes_time.csv` |

### Output

| Setting | What it does | Recommended |
|---|---|---|
| **Output folder** | Where the KML is written. | `output/` |
| **Output filename** | Name of the KML. A name is **suggested automatically** from the batch name + enabled features (e.g. `_stitched`, `_pos`, `_altcolor`). The existing files in the folder are listed with an overwrite warning. | Accept the suggestion. |

### Detection & sampling

| Setting | What it does | Recommended |
|---|---|---|
| **Confidence preset** | Bundles the detection/recovery aggressiveness. `strict` = airport-proximity matches only (no inference); `balanced` = full recovery at moderate tolerances; **`permissive`** = widest net for sparse coverage. | **permissive** (see §7) |
| **Sample interval (min)** | Point sampling interval; larger = smaller files, coarser lines. | **2** |
| **Max in-flight gap (min)** | A time gap larger than this splits one flight into two segments. | **20** |
| **Group by** | Organizes output KML folders by **origin** or **destination** airport. | **destination** (see note below) |

**Advanced overrides** (collapsed; blank = use the preset's value):

| Setting | What it does | Recommended |
|---|---|---|
| **Corridor cross-track (km)** | **The main recovery/noise knob.** How far off the real route corridor an inferred endpoint may sit. Lower = stricter/cleaner/fewer; higher = looser/more. | **50** with `permissive` |
| Airport match radius (km) | Airport-proximity radius for endpoint detection. | leave blank (preset: 100 permissive) |
| Max join gap (h) | Max time gap allowed when joining two fragments of one flight across files. | leave blank |
| Max join distance (km) | Max straight-line distance allowed for such a join. | leave blank |
| Route-time tolerance | How far an enroute time may deviate from the schedule and still match (fraction). Higher = looser. | leave blank |
| Route-time rescue | Force route-time rescue on/off, overriding the preset. | leave blank |

> **Group-by note:** "destination" clusters all arrivals into each airport — usually the most
> useful view for route/approach analysis. Switch to "origin" if you're analyzing departures.

### Styling

| Setting | What it does | Recommended |
|---|---|---|
| **Color mode** | `source` colors lines by data source (ADS-B / ACARS-POS / firehose / inferred); `altitude` colors by the **ADS-B Exchange altitude gradient**. | **source** (use `altitude` for altitude analysis) |
| Line color | Override the line color (source mode only), KML `AABBGGRR`. Blank = source's own color. | blank |
| Line width | Override line width in pixels. | blank (or `0.8` for thin) |
| Opacity (%) | Line opacity 0–100. | **100** |
| Show labels / airport icons / Extrude to ground | Per-flight name labels; airport markers; drop-lines to the ground under the 3-D track. | off |
| **Altitude bands** *(altitude mode)* | Number of discrete color steps in the gradient. More = smoother, slightly larger file. | **24** |

When Color mode = **altitude**, the **ADS-B Exchange legend** appears (orange at ground →
yellow → green → cyan → blue → violet/magenta at 40,000 ft+). Altitude mode takes precedence over
the Line color / source coloring.

### Gap Stitching

| Setting | What it does | Recommended |
|---|---|---|
| **Stitch coverage gaps** | Draw a straight-line connector across each coverage gap in a distinct color, marking the inferred (interpolated, not measured) portion. Off = one continuous track per flight. | on when you want inferred data flagged (see §8) |
| Inferred color | KML `AABBGGRR` for those connectors. | `ff888888` (gray) |
| Stitch gap threshold (min) | Minimum gap length that gets a connector. | **5** |

### Position Sources

| Setting | What it does | Recommended |
|---|---|---|
| **Integrate position sources** | Fill in-flight ADS-B gaps with **real** ACARS position reports and/or ADS-B firehose fixes (detection is unchanged; the extra sources only densify flights already found). | on only if you have POS/firehose data |
| ACARS POS folder | Folder of ACARS position-report JSON files (keyed to hex via the mapping CSV). | e.g. `/Volumes/jy-ext/…/pos` |
| ADS-B firehose folder | Folder of firehose position JSON files (carry ICAO hex directly). | e.g. `/Volumes/jy-ext/…/adsbpos` |
| Tail↔ICAO CSV | `tail_number,icao_hex` mapping (required to key ACARS POS to hex). | your active-tails CSV |
| POS color / Firehose color | Colors for the source-marked portions. | orange `ff00a5ff` / green `ff00ff00` |

## 7. Recommended configurations (worked examples)

All examples group by **destination** and use the two generated CSVs. Substitute your airline/batch.

### 7a. Standard run — the recommended baseline

The best-validated general configuration: widest net, tight corridor gate for clean results.

- **Preset:** *Recommended — clean & complete*
- Color mode **source**, group by **destination**, sample **2**, opacity **100**.
- Equivalent command line:

```bash
python3 adsb_historical_routes.py \
    --kml-folder ~/Git/kml/adsb_kml_downloader/output/poe_2026_jul-sept \
    --airports   input/poe_202606-202607_airports.csv \
    --routes     input/poe_202606-202607_routes_time.csv \
    --output     output/poe_routes_2026_jul-sept.kml \
    --confidence permissive --corridor-cross-track-km 50
```

**Output:** one continuous colored track per detected flight, organized into
`Destination → Route(ORIG-DEST) → flights`. A `.diagnostics.csv` sidecar lists every segment.

### 7b. Standard + gap stitching (mark inferred data)

Same as 7a, plus gray straight-line connectors wherever ADS-B coverage dropped and was bridged —
so downstream tooling can tell measured data from inferred.

- **Preset:** *Stitched — mark inferred gaps* (adds Stitch coverage gaps = on).
- Keep Inferred color `ff888888`, Stitch gap threshold **5**.
- Suggested filename gains `_stitched`.

**Output:** each flight becomes *N* real-data placemarks (its normal color) + *N−1* gray connector
placemarks. See §8 for tuning.

### 7c. Altitude-colored (ADS-B Exchange)

- **Preset:** *Altitude-colored* (Color mode = altitude).
- Altitude bands **24**; the ADSBx legend shows in the Styling section.
- Suggested filename gains `_altcolor`.

**Output:** each flight is split into altitude bands and colored orange→magenta by altitude, matching
the ADS-B Exchange map. Great for climb/cruise/descent and terrain analysis.

### 7d. Position-integrated (POS + firehose)

- **Preset:** *Positions integrated (POS + firehose)* (Integrate position sources = on).
- Set the ACARS POS folder, firehose folder, and Tail↔ICAO CSV.
- Suggested filename gains `_pos`.

**Output:** identical flight detection to 7a, but in-flight ADS-B blackouts are filled with real
ACARS/firehose fixes, color-marked orange (POS) / green (firehose). Where a source fills a gap, no
gray inferred connector is drawn.

### 7e. Strict — maximum precision, fewer flights

- **Preset:** *Strict — proximity only* (Confidence = strict).
- No inference or rescue at all; only airport-proximity matches.

**Output:** the cleanest subset — zero inferred data — at the cost of dropping flights whose tracks
truncate before the airport.

**Which preset?** Sparse coverage (Latin America, remote/oceanic, small fields) → **7a/permissive**.
Dense coverage (US domestic, most of Europe) → *balanced* is already excellent; 7a also works with no
downside. Want inferred data flagged → **7b**. Analyzing altitude → **7c**. Zero inference → **7e**.

## 8. Gap stitching & the best gap settings

ADS-B coverage often drops mid-flight and resumes; when the splitter joins two fragments of the same
flight, the span between them is a **straight-line inference**, not measured data. Stitching makes
that explicit.

**Recommended:**

- **Stitch coverage gaps:** on when the audience needs to distinguish measured vs inferred
  (analysis, QA, sharing); off for the simplest single-line-per-flight view.
- **Inferred color:** `ff888888` (gray) — visually recedes so real data stands out. Use a brighter
  color only if you specifically want gaps to pop.
- **Stitch gap threshold (min):** **5** is the sweet spot. Lower (2–3) flags even short dropouts
  (more, smaller connectors — noisier); higher (10–15) flags only long blackouts (fewer connectors,
  but some real interpolation goes unmarked).
- **Max in-flight gap (min):** keep at **20**. This is a *different* knob — it decides when a gap is
  so long the track is split into two separate flights rather than stitched within one. If legitimate
  single flights are being split in two, raise it; if two distinct flights are being merged, lower it.

**Stitching vs. position integration:** if you have real POS/firehose data (§7d), prefer that — it
*fills* gaps with measured fixes instead of inferring them, and gaps it fills are not drawn as gray
connectors. Stitching is the fallback when you have only ADS-B.

## 9. Reading the results

**Pre-flight card (before Run):** confirms *N KML · N airports · N routes*, shows the resolved
output path with an overwrite warning, lists any blocking errors (which disable Run), and prints the
**exact command line** that will execute — useful for learning the CLI or copying into a script.

**While running:** a progress bar with `processed / total` files and an ETA; phase markers
(`Loading position sources…`, `Combining segments…`, `Creating output KML…`); and a live console
mirroring stdout (toggle **All / Errors only**). *The console shows the last 500 lines — it's a live
tail, so on huge batches older lines scroll off; the full run is still summarized at the end.*

**Result:** a green **✓** (or red **✗**) with the parsed summary — valid flights, fixes filled (if
integrating positions), data reduction, gap connectors (if stitching), and the output file + size —
plus **Reveal in Finder** and **Run another batch** (which keeps your settings and re-suggests a
filename).

**The output KML** is organized `Group (destination/origin) → Route(ORIG-DEST) → individual flights`,
each flight a `gx:Track` carrying `lon lat alt` (altitude in meters). A `<output>.diagnostics.csv`
sidecar records every raw and final segment (disposition, airports, distances, rescue method) — the
basis for tuning without ground truth.

## 10. Colors (KML AABBGGRR)

KML colors are **`AABBGGRR`** (alpha, blue, green, red) — *not* RGB. The color pickers convert a normal
color + opacity for you, but if you type a raw value:

| Want | RGB hex | KML `AABBGGRR` |
|---|---|---|
| Red, opaque | `FF0000` | `ff0000ff` |
| Blue, opaque | `0000FF` | `ffff0000` |
| Gray (inferred), opaque | `888888` | `ff888888` |
| Orange (POS) | `FFA500` | `ff00a5ff` |
| Green (firehose) | `00FF00` | `ff00ff00` |

## 11. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| **Can't select the airports file in the browser** | You're looking for `Airports_2511.txt` — that's the OurAirports DB, not the airports file. Select the generated `*_airports.csv` (§1); build it with `build_cirium_inputs.py` if it doesn't exist (§4). The picker now also shows `.txt` files, but the splitter still needs the `airport,latitude,longitude,elevation_ft` CSV. |
| **Run fails immediately / "airports not found"** | The Airports CSV or Routes-time CSV field is empty or points at the wrong file (e.g. the raw Cirium export). Use the two generated CSVs (§1). |
| **Zero / very few flights** | Coverage is sparse — use the **permissive** preset with corridor 50 (§7a). Or the airports/routes CSVs don't cover this airline's network — rebuild them (§4) and check the `_error.txt` verdict. |
| **Too many mislabeled destinations** | Lower **Corridor cross-track (km)** (e.g. 50 → 40). It's the main recovery/noise knob. |
| **Browser tab froze on a big run** | Fixed — the console now batches and caps output. Hard-refresh the page to pick up the latest UI. |
| **Output folder / POS folder "outside the allowed folders"** | The server confines file access to `roots.allowed_roots` in `route_builder/manifest.json`. Add the location (e.g. your data volume) there and restart the server. |
| **Legitimate single flights split into two** | Raise **Max in-flight gap (min)** above 20. Two distinct flights merged into one → lower it. |
